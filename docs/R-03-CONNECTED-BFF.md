# R-03 browser profile handoff

The private proactive server can accept the Recruiting Connected App BFF as an explicit alternative to the legacy signed-link resolver. The BFF requests `recruiting.candidateSearch`, obtains an audience and profile-bound token from Control Plane through Authorization Code and PKCE, stores it server-side, and introspects it for each protected page, API read and command. The real page and API still call the same R-03 handlers and vacancy ownership check. A browser profile switch or revoked membership causes the next request to fail; it never changes an already accepted search occurrence.

The two auth modes are exclusive in one server instance. BFF mode rejects legacy `username`/`token` URL selectors and has no fallback to the old signed-link cookie. Unsafe commands require the BFF's Origin and CSRF token checks; the browser fetches that token from its own `/auth/connected/session` endpoint. An introspection outage returns a typed unavailable response and does not invoke a domain handler. Legacy signed-link mode retains its existing Origin check and browser behavior.

The injectable BFF and in-memory store are suitable for contract tests only. A production launch still needs a durable atomic BFF store, registered Control Plane client and exact HTTPS callback, a reviewed principal/profile membership, and a trusted Control Plane browser-session resolver. The private CLI does not construct or activate this BFF yet; default startup remains legacy signed-link mode. No public route, timer or profile binding is changed by this slice.
