# R-01: first HH response read

This slice reads one live HH `response` negotiation page for an already trusted profile and an explicitly selected, owned vacancy. It preserves the HH negotiation and resume IDs as provider refs. The service loads the token from its server-side profile credential broker, sends `GET /negotiations/response?per_page=20&page=N&vacancy_id=...` with a host-configured `HH-User-Agent` name/contact header, refreshes once after 401, and projects a bounded response. Provider errors, malformed pages, a foreign vacancy and missing credentials return typed failures; no cached list is presented as current.

`GET /api/v1/ui/hh-responses?vacancyId=...&page=0` and `/hh/responses?vacancy_id=...` are mounted by the opt-in private web runtime only with Connected App BFF. The runtime wires the real profile credential broker and exact host-owned vacancy bindings. The default demo server and legacy signed-link private mode do not expose this page. Queryless `/auth/connected/start` still requests only `recruiting.candidateSearch`; `/auth/connected/start?from=responses` explicitly requests only `recruiting.responses.read`. A candidate-search session entering `/hh/responses` is redirected to that step-up; a missing grant fails at callback and leaves the old candidate-search session intact. The selected vacancy is an exact safe return path, never a supplied URL. The read-only page exposes HH fetch time and best-effort page navigation. No provider token reaches the browser.

This is an offline implementation and proposed route, not a live release. `infra/nginx/recruiting-responses.locations.conf` must be reviewed together with the existing Connected BFF auth-route snippet. Public nginx remains unchanged pending real CP membership and client registration, private HH provider canary, and route cutover review. No agent capability or MCP facade is declared for this UI read, so an MCP parity assertion is not applicable to this slice. If a response-read capability is later declared for agents, its real transport and handler need independent contract tests.

The page contract is [`v1-live-hh-response-page.schema.json`](../contracts/v1-live-hh-response-page.schema.json). `fetchedAt` means HH answered this request; `sourceRevision` hashes this page only. HH page-number pagination can shift when negotiations arrive or change state, so `paginationConsistency: best_effort` is explicit. It must not be treated as a complete, gap-free snapshot. A later R-01 slice needs pinned or reconciled multi-page reads, selected-vacancy persistence, resume/history context, UI and agent relay parity. Sending, moving, rejecting, draft generation and client reports remain separate commands and sources.

The tests use invented profiles, candidates, tokens and HH-shaped responses. They run the real private HTTP entrypoint, durable BFF, reader and credential broker with external CP/HH responses replaced; they cover two profiles, separate scopes, callback replay, CSRF gates, 401 refresh, provider failure, cross-vacancy rejection, page navigation and introspection outage. No real HH or user data is used.
