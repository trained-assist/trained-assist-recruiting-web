# R-03 five-minute background scoring foundation

The operator scenario is: after a scheduled cold search, the recruiter opens the morning candidate list and sees ATS assessments as they arrive. `runHhBackgroundScoringTick` is one bounded pass for an **external five-minute timer**. It reads only the latest completed search for an explicitly owned profile and vacancy, sends at most `limit` (default 10, max 100) candidates to an injected evaluator, and writes validated assessment fields into the same private SQLite candidate-state file. A deployment must supply the timer, trusted scope, canonical criteria-revision resolver and evaluator. This repository supplies none of those production ports and does not enable a timer.

The assessment is `{atsScore, atsTag, knockout}` under `contracts/v1-real-hh-assessment.schema.json`. A failed knockout needs named criteria and caps the score at 2, matching the legacy rule. The evaluator receives a mapped candidate projection rather than raw HH JSON. Search snapshots and their original pre-scores remain immutable. `assessedResultPage` overlays recorded assessments for a job; the existing `resultPage` still returns the original snapshot. A score is bound to profile, vacancy, job, resume, and a SHA-256 revision of criteria, source and candidate projection. A SQLite immediate transaction checks that the job is still the latest and that the candidate projection matches before first-wins insertion. A late evaluator result after a new search is discarded. Two writers may evaluate the same candidate, but only one result commits; the production timer should also use one host-wide lease to avoid duplicate evaluator cost.

The worker checks the canonical criteria revision before and after evaluation. This is a best-effort check while that revision lives outside this SQLite transaction. Production must place the canonical revision under the same transactional owner, or use a revisioned evaluator result with a trusted compare-and-swap port, to close the final config-change race. Exceptions from the evaluator are counted without returning or logging candidate text. Bad assessment shapes fail closed and can be retried on a later tick. The timer should use a fixed five-minute interval with no overlapping ticks, private logs, bounded evaluation latency, and health checks for persistent pending/error counts.

Offline tests use invented candidates and an injected evaluator. They cover restart, immutable snapshots, latest-job fencing, criteria changes, two SQLite writers, profile isolation, invalid score rejection and error redaction. This is not connected to the public `/hh/proactive` page or current synthetic schedule worker. Live LLM/HH access, migration of legacy score state, feed aggregation, authentic profile binding, timer installation, monitoring and cutoff acceptance under HH #187 remain open.
