# R-02 response evaluation foundation

This slice demonstrates a read-only evaluation of one fully synthetic incoming response. It is a foundation, not production R-02 completion. The route `/api/v1/ui/response-evaluations` is a local UI fixture route and is deliberately absent from the C14 manifest, capabilities and endpoint discovery. The server's default trusted-profile resolver denies access. A host must inject a resolver backed by trusted out-of-band identity and scopes before any profile route could be used; the test resolver is only a test stub.

The request contains a response, vacancy and expected response, resume and vacancy-criteria revisions. It never accepts a profile identifier. The handler checks profile ownership and response/vacancy pairing, then rejects any changed revision before invoking the deterministic synthetic evaluator. The output carries the source revisions and a stable ID derived from those revisions. It contains typed evidence and gaps. Invalid adapter output fails closed. No LLM/provider, persistence, message, candidate ranking, HH state change or external side effect is used.

## Legacy comparison

Inspected `trained-assist-hh-skill` at `af25f267bd20498c02f578b7b77ffc587dad3e85` (local `main`; checkout was 17 commits behind `origin/main` at inspection): `src/hh-eval-canonical.js`, `src/hh-eval-adapters.js`, `src/hh-eval-job.js`, and `tests/unit/hh-eval-job.test.js`. The canonical evaluator is a pure module with normalized scoring rows, evidence, expert checks, veto/verdict and coverage; its evaluation identity incorporates candidate/vacancy, requirements revision, policy version and document digest. The job layer assembles profile-file and ATS/portrait criteria, candidate documents, and optional interview evaluation, calls an LLM scorer, persists progress/results, and builds cross-source comparison pools.

This foundation intentionally does not copy that job orchestration or scoring model. It uses criterion-mapped synthetic resume facts and emits only `meets`, `partial`, or `does_not_meet` plus missing-evidence gaps. Its revision tuple is a synthetic fixture contract, not a verified source-of-truth freshness mechanism. Production criteria ownership, evaluation policy/version, candidate document lineage, interview inputs, scoring semantics, audit/persistence ownership, and trusted identity/scope integration remain unresolved. Reinspect the legacy source at its current revision before adopting behavior.
