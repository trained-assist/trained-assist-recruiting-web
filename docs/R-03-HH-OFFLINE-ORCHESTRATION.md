# R-03 offline HH cold-search orchestration

`src/hh-cold-search-offline.js` joins the isolated real-HH ports without enabling them in a route or timer. Both `manual` and `scheduled` calls use `run({ trustedContext, vacancyId, jobId, source, expectedCriteriaRevision, expectedQueryRevision })`. The trusted `loadSearchPlan` port supplies a profile/vacancy-bound ATS config, explicit area (`null` means unrestricted), and a revisioned cache of 1–15 search queries. This matches the legacy manual query editor's 15-query cap; generated queries are normally fewer. A missing or changed plan fails closed.

For each query, the injected HH transport fetches at most 50 resumes. The runner maps each response, deduplicates HH IDs across queries, and retains the full post-experience candidate pool; six complete responses can produce more than the synthetic 200-result limit. The final plan is checked again, then one `hh-result-v1` transaction records candidate pool, seen IDs and snapshot. No candidate becomes seen or fresh if the third query fails, a mapping fails, a profile/area binding changes or the final commit fails. The source revision hashes criteria, query cache, area and ATS config. A matching completed job is read without repeating provider requests; conflicting revisions fail closed.

The tests use only invented HH-shaped responses, an injected fake token and mock `fetch`: 295 candidates across six queries, explicit unrestricted and numeric geography, retry failure mid-batch, cache/criteria staleness, one shared scheduled/manual handler, database restart, deterministic result pages and no PII in errors/logs. The orchestration does not launch Agent Run or use ambient network access.

This is an offline integration foundation. The persistent job/occurrence owner is not connected to this runner. Production still needs a trusted search-plan and credential implementation, OAuth refresh ownership, HH/LLM access, ATS assessment and five-minute rescore, authenticated page/API, scheduling/unknown-outcome reconciliation, data migration and verified non-GCP hosting. The synthetic handlers and validators remain unchanged; no live token, HH call, schedule activation or route cutover occurred.
