# R-03 durable real-HH manual runs (offline)

`SqliteRealHhManualRuns` is the real-HH domain counterpart of the synthetic async manual-search contract in [PR #24](https://github.com/trained-assist/trained-assist-recruiting-web/pull/24). It accepts a trusted profile context, owned vacancy, idempotency key and expected criteria/query revisions. One SQLite row persists the run and a stable job ID before the injected `createOfflineHhColdSearch` runner is dispatched. Polling and identical start replay read the same row after restart. No automatic retry occurs. An expired running lease becomes `outcome_unknown`; a late worker cannot turn that row into success. The real-HH candidate state owns the resulting snapshot, seen IDs and paginated result data.

The public status has separate `search` and `atsRefresh` fields. A completed search reports `atsRefresh: pending`, meaning the separate five-minute scorer has **not** been implemented here. The real shape is checked by `contracts/v1-real-hh-manual-run.schema.json`; it uses real job IDs and vacancy IDs, and `rejected` for known pre-dispatch failure. PR #24's schema and routes remain synthetic. A later route adapter must add the real request/query revision mapping and update the route schema before replacing that adapter. This PR does not bind public HTTP, MCP or trusted web sessions.

Tests use invented candidate data and an injected search port. They cover scheduled and manual search sharing one real-HH pool/seen store, durable polling/replay, profile isolation, stale-plan rejection, process restart, lease expiry, no repeated provider call and independent ATS status. There is no live HH request, credential or deployment. A run left `outcome_unknown` despite a committed snapshot needs a separate manual-run reconciliation design; the occurrence reconciler from the previous slice handles only scheduled occurrences. HH #187 remains a production stop gate.
