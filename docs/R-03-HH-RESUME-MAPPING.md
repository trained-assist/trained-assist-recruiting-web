# R-03 HH resume mapping and pre-score

The pure `src/hh-resume-mapping.js` maps a `/resumes` item into an internal HH candidate projection. It has no fetch, credential, persistence, logger or Agent Run path. Tests use an entirely invented HH-shaped response under `test/fixtures/hh-resumes-invented.json`.

Source compared with `trained-assist-hh-skill` `origin/main` at `60566b5e9c4feee5e5a57ed1b2c93214082fb70e`, `src/hh-proactive-search.js:13-115` and `1018-1063` (line positions at that revision). Normalization accepts `required`/`required_skills`, `preferred`/`preferred_skills`, string or object `knockout`, and the current or historical minimum-experience key. The deterministic exclusion is **minimum experience only**. Legacy `scoreCandidate` matches significant words from title, experience and certificates, adds criterion weights to a 1.5 experience base, and ranks for AI assessment. It does not evaluate arbitrary knockout criteria. The mapping marks those criteria `pending_ai`, sets `atsScore`/`atsTag` to null, and labels its threshold tag `preTag`; it must not be shown as a final ATS verdict. The pure page mapper deduplicates by HH ID and sorts by pre-score, matching the legacy pre-enrichment order.

The existing synthetic job and candidate-state DTOs deliberately cannot hold the real projection. `src/candidate-search-jobs.js` accepts only `candidate_search_demo_NNN`, `cold-search-provider-demo-rN`, and exactly five display fields; `src/candidate-state.js` stores a display title/region/summary plus one 0–10 review score. The real projection additionally carries HH resume ID and URL, name, age, salary, structured experience, first-found metadata, pre-score and signals, pending/finished ATS assessment, tags and knockout evidence. The old store also maintains per-vacancy overlays, seen dates and accumulated snapshots. Mapping raw HH data into the fixture DTO would discard this information and violate its validation contract.

Next integration step: define a versioned real-HH search result contract and persistent candidate model with explicit PII access rules, retention, candidate/vacancy identity and assessment revisions; then adapt the transport result through this mapper into that model. The same scheduled and manual handler must commit the full post-experience pool, seen IDs and snapshot atomically before marking results fresh. Add ATS/LLM scoring and background rescore as a separate owner of the assessment fields with idempotent revision checks. Keep provider access behind the trusted credential/context ports and validate the whole path using invented fixtures before any real HH call or public route cutover.

No synthetic validator/state was changed, and this slice makes no network request or production write.
