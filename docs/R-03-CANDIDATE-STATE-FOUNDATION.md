# R-03 candidate state and sanitized import foundation

This slice defines `v1` profile-owned candidate state for one canonical candidate identity with vacancy-specific review, a per-vacancy seen ledger, dated completed-run snapshots, comments and query revisions. The runtime projection lists the accumulated candidate pool for an owned vacancy. The latest snapshot supplies freshness and run statistics; it is not the whole feed. A candidate with empty legacy `vacancy_ids` remains visible in every **authorized** vacancy view, with an `active` default review where no vacancy overlay exists. The injected `isVacancyOwned` check defaults to deny; a live adapter must derive ownership from trusted profile context, not a request body.

`recordSearch` stages the full filtered pool before seen IDs, then appends the completed snapshot. The in-memory adapter commits all three atomically and a failed stage commits none. A production adapter must preserve that transaction and profile binding in durable storage; this file is not a production persistence layer. Manual source and original `foundAt` survive a later search merge. Every nonempty recruiter comment changes the per-vacancy query revision and invalidates generated queries, matching legacy `getSearchExclusions`; the `excludeFromSearch` field is retained only as a proposed UI hint. A separate background scoring writer must update the same candidate and snapshot state under the same vacancy key before it can be enabled.

`planLegacyImport` is a dry-run converter for reviewed, **synthetic** legacy-shaped data. It accepts only the explicit allowlist and fake ID/text patterns, checks trusted vacancy ownership and that every seen/snapshot reference has an accessible candidate in the pool, and returns a `v1` state plus counts without writing. It preserves recruiter-pinned manual queries; generated legacy cache entries are discarded because their old hashes do not establish the new criteria revision. [`r03-legacy-sanitized-golden.json`](../data/r03-legacy-sanitized-golden.json) is hand-authored, not a copy of a private export. Live import needs a restricted-environment inventory/redaction pass, source checksums, conflict/reconciliation decisions, transactional restore, audit, and a separate canary gate.
