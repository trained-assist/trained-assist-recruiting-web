# R-03 private proactive web runtime

`src/r03-private-web-runtime.js` composes the existing private host config, SQLite schedule/candidate/manual-run stores, HH search stack, accumulated feed and real `/hh/proactive` handlers. It binds only to `127.0.0.1` when explicitly run with `--live-execution --config ... --secrets ... --port ...`. Construction does not call HH or LLM. No service unit, nginx route or public bind is installed by this change.

The private credential directory needs `legacy_page_secret` equal to the old agent's `AGENT_SECRET`, plus `hh_encryption_key`, `hh_client_id`, `hh_client_secret` and `ladder_token`. The legacy secret is never placed in config, query cache, logs or repo. Each web-exposed profile needs an explicit, unique `legacyUsername` in the owner-only host config; it may differ from target `profileId`. The old page link's 16-hex HMAC is checked over `legacyUsername`, then resolved to the target profile. The unsigned `vacancy_id` is checked against that target's private vacancy binding. A link without `vacancy_id` works only when that target profile has exactly one bound vacancy. An absent mapping denies both signed entry and an old cookie after restart. This prevents a guessed selector or ambiguous default from widening access. After a successful page request, the service issues a 12-hour `Secure`, `HttpOnly`, `SameSite=Strict`, host-only cookie tied to the target profile and a distinct HMAC purpose. Browser API requests use the cookie. Mutations require the exact public `Origin` as a CSRF guard. The private runtime exposes only `/health/ready`, `/hh/proactive` and `/api/hh/proactive/*`; other synthetic service routes return 404.

The page displays accepted accumulated candidates. `GET /api/hh/proactive/candidates`, `GET schedule`, `GET occurrences`, `GET manual-runs/{id}`, `POST search`, `POST vacancy-state` (`enable`/`disable`), `POST comment` and `POST set-status` are wired to the real SQLite-backed operations. Manual search is asynchronous and requires `Idempotency-Key`; the page does not yet offer controls for those actions. A legacy browser's JSON `username`/`token` POST form is **not** a compatible client of these routes; it must reload this new page and use its cookie, revised command shape and polling.

Legacy `/api/hh/proactive/ai-score`, `/import-seen`, and `/add-manual` remain unsupported. The target-side [prompt editor](R-03-PRIVATE-PROMPT-EDITOR.md) now serves `/prompt`, with revisioned commands instead of the old JSON shape. Legacy `vacancy-state` star/unstar/archive/restore flags also remain unsupported; review actions use `set-status`. Unsupported real-mode routes return 501. The nginx route must stay on GCP until these user-visible functions are either implemented or explicitly removed, along with restore and HH/LLM canaries. This PR contains only invented test data; no production profile binding or secret is committed.
