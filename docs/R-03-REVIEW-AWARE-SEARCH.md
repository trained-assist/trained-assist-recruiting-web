# R-03 review feedback in the HH search plan

Recruiter comments and explicit `excludeFromSearch` flags now have an offline path into the next cold search. The private candidate-state SQLite DB computes a vacancy-scoped feedback revision from comments and excluded resume IDs. `createReviewAwareSearchPlan` wraps the trusted base `loadSearchPlan`; it receives comments, asks an injected query generator for a new 1–15 query set, and stores the generated set under the base query revision plus feedback revision. The first validated output wins if two workers generate concurrently. Subsequent plan reads and process restarts reuse it. Recruiter-pinned manual queries stay pinned, while their revision still changes when feedback changes.

The resulting plan carries `excludedResumeIds`. `createOfflineHhColdSearch` filters those IDs from the candidate snapshot, preserves the raw collected count and hashes exclusions into the source revision. It reloads the plan after HH collection; a changed comment, exclusion or query revision prevents a stale result from committing. Status changes alone remain display state and do not regenerate queries. Feedback is isolated by profile and vacancy.

Tests use invented candidates and an injected deterministic query generator/HH transport. They cover one generated query set across a pre/post plan read and restart, vacancy isolation, manual pinned queries, exclusion filtering, status-only stability and comment changes during collection. No live LLM or HH call is added. Production still needs a canonical ATS/query owner and injected generator, private profile binding, the real timer/host, and an operator decision on legacy comments without vacancy IDs. The old GCP routes remain active under HH #187.
