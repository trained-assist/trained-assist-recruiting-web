# R-03 private HH search composition

`createPrivateHhSearchStack` connects the profile-scoped ATS/query reader, review-aware query cache, credential broker, HH transport, atomic candidate state and durable schedule occurrence worker. The host injects identity and vacancy ownership, owner-only restored directories, private SQLite stores, a query generator, OAuth secrets, HTTP and clock. The stack makes no request or schedule change at construction.

The invented integration fixture imports one disabled legacy schedule, checks that it does not run, then uses the offline activation port with explicit synthetic readiness evidence. Its due tick reads the private profile plan and token, refreshes one invented 401, collects two full HH pages (100 candidates), commits one candidate/seen/snapshot transaction, finishes the occurrence, and serves both cursor pages of the morning result. A repeated tick does not dispatch again. The test runs without network or personal data.

This is still a composition test. The readiness callback in the fixture is invented; it is **not** proof of a restored backup, authorized HH canary, deployed timer or production operator decision. A deployment must supply a real profile binding and authenticated operator, verify actual private import receipts and secrets, provide query regeneration and evaluation, run the minute and five-minute timers, and switch public routes only after the existing URL/API parity tests and canary pass. The eight unknown historical outcomes stay quarantined until investigated; they are never replayed by this stack.
