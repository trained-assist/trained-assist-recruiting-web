# R-03 on-demand ATS assessment

A recruiter can click **Оценить ATS сейчас** on a candidate in the accepted morning feed. The page posts an explicit `vacancy_id`, `candidate_id` and `expected_job_id` under its profile cookie and public Origin. The private runtime checks profile scope and vacancy ownership, exact accepted feed membership and the displayed job revision. It returns an existing score without another LLM call. A pending candidate is eligible for one bounded evaluation only when its job is also the latest stored snapshot; older accumulated candidates return `409` until a current accepted search includes them. A newer unaccepted snapshot also holds scoring rather than publishing a result against an uncertain run.

The endpoint uses the same 0–10 ATS evaluator, criteria revision and SQLite first-wins assessment record as the five-minute scorer. It reads the base plan without generating search queries, compares criteria before and after the evaluator, deduplicates concurrent clicks in the web process, and bounds the wait to 50 seconds. SQLite rejects a result after a newer snapshot or candidate projection. A failure records the existing backoff and returns a generic error without provider text. The UI shows the numerical ATS score and tag. It does not claim the old `ai-score` narrative or 0–12 scale; that parity difference must be accepted or implemented before public route cutover. This slice does not switch nginx or make a live provider call.
