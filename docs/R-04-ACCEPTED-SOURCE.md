# R-04: accepted candidate as a report source

This read selects a candidate from the durable R-03 accepted feed under a trusted profile and owned vacancy. It requires the candidate to be in the latest stored search snapshot, still active or starred, with a persisted ATS assessment bound to the current vacancy criteria. The source revision includes the feed, snapshot, criteria, assessment and review revisions. A concurrent feed or criteria change rejects the read rather than returning a seemingly current source.

`GET /api/v1/ui/accepted-report-source?vacancyId=...&candidateId=...` is available only when a host injects `acceptedReportSourceRead` and a trusted resolver grants `recruiting.reports.read`. The demo and R-03 private host do not mount it. It is absent from C14 discovery until a dedicated report session and agent relay are accepted. The exact response is in [`v1-accepted-report-source.schema.json`](../contracts/v1-accepted-report-source.schema.json).

The route returns two separate projections. `clientDraftFields` allows only candidate name, position, vacancy title and position/company/period experience. `internalAssessment` contains score, tag, review status and criteria revision; it is never copied into the client draft. Salary, age, contacts, HH URL, recruiter comments, ATS context and knockout details are excluded. These are *draft proposals* for recruiter review, not approved sharing or publication. `publication: disabled` is fixed. No report is stored or rendered by this read.

Current legacy report flows include independent HTML, Markdown and JSON generation; this slice sources only accepted cold-search candidates. Incoming responses need their own source binding. The existing synthetic report draft store is not connected to this reader because it has synthetic candidate IDs and no durable source/audience policy. Before a real draft or client link can be enabled, the product must decide authorized client fields and consent, reconcile the report notes/forbidden-phrase rules, persist report/edit/audit history, define access and expiry, and make unknown publish outcomes recoverable. Offline tests cover scope, foreign vacancy, stale criteria/feed, incomplete assessment, archived candidates, revision changes and exclusion of internal fields.
