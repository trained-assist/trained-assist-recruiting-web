# R-03 imported schedule activation, offline operator port

`R03LegacyScheduleActivation` operates only on definitions previously imported by `R03LegacyScheduleImport`. It requires an authorized operator, the exact migration/job/definition digest, a private evidence digest, and an explicit disposition for a legacy `unknown` outcome. `confirmed_no_dispatch` and `reconciled_in_target` are the only accepted investigated dispositions; `not_applicable` is allowed only for definitions without an unknown outcome. The injected readiness port must attest profile/vacancy binding, ATS and query availability, an HH credential check, verified candidate restore, and the background writer delta.

Activation is one SQLite transaction: it rechecks the imported definition and quarantine, rejects any target occurrence or lease, clears the migration block, enables the schedule, sets the next occurrence strictly **after** the activation time and writes an audit receipt. It does not replay missed legacy slots. An identical command returns the same receipt; a changed command conflicts. `suspend` is an operator rollback that disables and quarantines an activated schedule with its own receipt. Re-activation after rollback needs a separately reviewed new cutover procedure.

All tests use invented 10+1 schedule metadata. This port has no production operator issuer, actual private evidence, HH credential, restored data, installed timer or live activation. The callback's booleans are offline contract inputs, not proof that the checks occurred on a host. HH #187 stays open until a real target passes the full scheduled cycle and page/API checks.
