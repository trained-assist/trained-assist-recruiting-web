# R-03 accumulated real-HH candidate feed foundation

The recruiter opens a vacancy in the morning and sees everyone found across completed searches, including candidates from older runs. `createR03AccumulatedRealFeed` reads the private real-HH SQLite state for one trusted profile and vacancy. It includes completed manual snapshots and scheduled snapshots whose occurrence is `succeeded` and whose stored source/result revision and count match the occurrence receipt. A committed snapshot from an unknown occurrence stays quarantined. If a newer schedule occurrence is incomplete or unknown, the last accepted feed is labeled `latest_run_incomplete`.

The feed deduplicates by resume ID within a profile/vacancy, shows the latest accepted projection, overlays a revision-matched ATS assessment, and sorts assessed candidates first by ATS score, then by pre-score. It retains older candidates when a later search omits them. A vacancy-scoped overlay stores `active`/`starred`/`archived`, a private comment and `excludeFromSearch`, with optimistic revision checks. The service checks accepted feed membership before an overlay write. The search plan does not yet consume `excludeFromSearch`; this flag must be wired before claiming exclusion behavior. The same resume in another vacancy or profile has separate status/comment. The SQLite file and its WAL remain owner-only as described in `R-03-REAL-HH-CANDIDATE-STATE.md`.

Only candidates with explicit profile and vacancy binding in a validated search snapshot enter this feed. Legacy global candidates without vacancy IDs are **quarantined**, not assigned to every vacancy by guesswork. Private migration needs a reviewed mapping or explicit exclusion receipt for each such record. The tests use invented candidates across two profiles and two vacancies, scheduled/manual results, a repeated candidate, score/review overlays, restart, an unknown newer run and wrong-vacancy rejection.

This is an offline domain read, not an HTTP endpoint or a production migration. The current implementation bounds each feed at 50,000 accepted snapshot members and 1,000 succeeded occurrence IDs, failing closed at capacity. Production needs indexed pagination, a retention/deletion policy, authenticated page/API, real profile and vacancy binding, imported data and real HH/LLM acceptance before HH #187 can close.
